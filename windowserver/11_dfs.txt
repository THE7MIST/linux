-------------------------------
1. THEORY: DFS OVERVIEW
-------------------------------

DFS (Distributed File System)
→ Provides access to same data from multiple locations
→ Data stored on different physical servers but appears unified

Purpose:
→ Centralized access
→ Load distribution
→ Fault tolerance
→ High availability

Example:

BEFORE DFS:
X: \\S1\Doc
Y: \\S2\Pic
Z: \\S3\Med

AFTER DFS:
Single path:
\\DFS01\sharedfiles
   → Doc
   → Pic
   → Med


-------------------------------
2. TYPES OF DISTRIBUTED FS
-------------------------------

→ Windows DFS

→ SMB (Server Message Block)
→ GFS (Google File System)
→ Lustre
→ HDFS (Hadoop Distributed FS)
→ GlusterFS
→ More...


-------------------------------
3. HOW DFS WORKS
-------------------------------

A. DISTRIBUTION
→ Data split across multiple servers (nodes)
→ Each node contributes computing power
→ Parallel processing enabled

B. REPLICATION
→ Same data copied to multiple servers
→ Ensures:
   → Fault tolerance
   → High availability
   → Data recovery

C. DFS NAMESPACE
→ Virtual folder containing links
→ Links point to shared folders on different servers


-------------------------------
4. DFS STRUCTURE (CONCEPT)
-------------------------------

Namespace Server
   ↓
Namespace Root (e.g., \\MASTER\DFS01)
   ↓
Folders (Links)
   ↓
Folder Targets (Actual Shares)

Example:
\\MASTER\DFS01
   → Tools → \\FS01\Tools (London)
            → \\FS02\Tools (New York)
   → Docs  → \\FS02\Doc


-------------------------------
5. DFS REPLICATION
-------------------------------

→ Replication duplicates data across servers
→ Sync between 2 or more locations

Replication Group:
→ Members (servers)
→ Replicated folders

Example:
Projects + Documents replicated
Between:
Server1 ↔ Server2
